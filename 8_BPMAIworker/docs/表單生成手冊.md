# .form 生成手冊

> 依據：`samples/快速開發測試/表單/原檔案-quickDevTestForm.form`（222 KB、747 個 XStream 節點、27 種元件）
> 與 `samples/太陽能ECRECN/表單/SolarEnergyECRECN.form`（853 KB、上線中）的實際結構分析。
> 產出物的解析與驗證一律用 `1_xml_tool/core/form_handler.py`，本文不重述其實作。

---

## 1. 檔案骨架

`.form` 是 XStream 序列化的 `FormDefinition`，**沒有 XML 宣告列**，根節點直接開始：

```xml
<com.dsc.nana.domain.form.FormDefinition id="1">
  <appDesignType id="2"><value>-1</value></appDesignType>
  <authorName>系統管理員</authorName>
  <containerOID>3c184ddcf9e21004851cac97a977dbbf</containerOID>
  <createdTime id="3">2026-08-20 14:22:09.0</createdTime>
  <dataAccessDefinitions class="list" id="4"/>
  <description></description>
  <EleCountForDesigner>0</EleCountForDesigner>
  <elementDefinitions class="list" id="5">
     ... 所有元件 ...
  </elementDefinitions>
  <formDefinitionStyles>...</formDefinitionStyles>
  <id>quickDevTestForm</id>
  <labelAlign>...</labelAlign>
  <labelProportion>...</labelProportion>
  <mobileScript>...</mobileScript>
  <multiZhMap .../>
  <name>快速開發測試</name>
  <processCommentType>...</processCommentType>
  <publicationStatus>...</publicationStatus>
  <rwdLayout>... 逃脫過的版面 JSON ...</rwdLayout>
  <script>... 逃脫過的 JavaScript ...</script>
  <sqlCmds .../>
  <validFrom>...</validFrom>
  <version>...</version>
  <scriptInfo>...</scriptInfo>
  <mobileScriptInfo>...</mobileScriptInfo>
  <SET__PROXY__CLASS__NAME>org.apache.ojb.broker.accesslayer.SetProxy</SET__PROXY__CLASS__NAME>
  <LIST__PROXY__CLASS__NAME>org.apache.ojb.broker.accesslayer.ListProxy</LIST__PROXY__CLASS__NAME>

  <objectVersion>1</objectVersion>
  <dto>true</dto>
  <dtoState><value>0</value></dtoState>
</com.dsc.nana.domain.form.FormDefinition>
```

**組裝器只需要動三個地方**：`elementDefinitions`、`rwdLayout`、`script`（與 `mobileScript`）。
其餘全部沿用樣板值。

## 2. ★ XStream 連號 id —— 最硬的一條規則

實測 `原檔案-quickDevTestForm.form`：

```
id="1" … id="747"   嚴格連號，無跳號、無重複
reference="8"       出現 46 次，指向 <cssDevice id="8">
```

含意：

1. **`id` 屬性不是元件 ID**，是 XStream 的物件序號。`<id>xxx</id>` 子標籤才是元件 ID。
2. 每插入一個元件（一個 `InputElementDefinition` 大約帶 15～20 個帶 `id` 的子節點），
   **其後所有節點的序號都要 +N，所有 `reference="M"` 也要同步 +N**。
3. 因此**絕不可以用字串拼接的方式把樣板片段直接貼進去**。
   組裝流程必須是：先決定完整元件清單 → 再一次走訪全檔重新編號。

`1_xml_tool` 之所以只做「改 ID」不做「加減元件」，就是這個原因。

> ⚠️ 尚未驗證：設計師匯入時是否真的檢查連號。在確認之前，一律當作它會檢查。

### `.form` 與 `.bpmn` 的 reference 模式不同

| 檔案 | reference 寫法 | 例 |
|:---|:---|:---|
| `.form` | **數字**（XStream ID mode） | `<cssDevice reference="8"/>` |
| `.bpmn` | **相對路徑**（XStream XPATH mode） | `<dtoState reference="../../../../../header/dtoState"/>` |

同一套序列化框架、兩種模式，**處理程式不能共用**。

## 3. 元件與中文標籤的配對機制

鼎新**不把中文名稱存在元件裡**，而是另外放一個 `OutputElementDefinition`（Label）：

| 配對方式 | 說明 | 優先序 |
|:---|:---|:---:|
| `lbl_` 前綴 | Label 的 `<id>` 是 `lbl_{元件ID}` | 1 |
| `pairId` | Label 與元件共用同一個 `pairId` | 2 |
| `caption` | 按鈕（`TriggerElementDefinition`）自己有 `caption` | 3 |
| `textValue` | 元件自身的 `textValue` | 4 |

（優先序即 `form_handler.FormElement.display_name` 的判斷順序。）

**生成規則**：IR 裡每個有 `label` 的欄位，都要同時產生
1. 元件本體（`<id>` = IR 的 `id`，`<name>` 同值）
2. 一個 `OutputElementDefinition`，`<id>` = `lbl_{id}`、`<name>` 同值、`<textValue>` = IR 的 `label`

漏掉 Label 的後果不是報錯，是**表單上看不到欄位名稱**，
以及日後稽核匯出（`7_proc_export`）只能顯示欄位 ID。

## 4. 各元件型別的必備子標籤

一個元件動輒 3～4 KB，其中絕大多數是樣板。**只有下表這幾格是 IR 決定的**：

| 元件類別 | 直屬子標籤數 | IR 要填的格 |
|:---|:---:|:---|
| `InputElementDefinition` | 40 | `controlType`、`id`、`name`、`isRequired`、`hint`、`length`、`pairId` |
| `SelectElementDefinition` | 29 | `controlType`、`id`、`name`、`selectListItems`（選項）、`isMultiSelect`、`pairId` |
| `TriggerElementDefinition` | 16 | `caption`、`id`、`name` |
| `ListElementDefinition` | 30 | `id`、`name`、`listItems`（欄位定義）、`addControlButton`／`updateControlButton`／`deleteControlButton` |
| `OutputElementDefinition` | — | `id`、`name`、`textValue`、`pairId` |

其餘（`cssStyle`、`elementStyles`、`navindex`、`precision`、`scale`、
`persistentType`、`validationRules`、`multiZhMap`…）**一律照樣板複製**，
不要試著理解或最佳化——那是設計器 UI 的內部狀態。

### `elementStyles` 是每個元件 4～5 份

實測 `SolarEnergyECRECN.form` 有 420 個 `ElementStyle`、124 個元件——
每個元件對每種裝置（`device` 值 0／3／5…）各一份樣式。
IR 不描述樣式，組裝器一律照樣板產生同一組。

### 選項（`SelectItem`）與表格欄位（`ListItem`）

```xml
<com.dsc.nana.domain.form.ListItem id="564">
  <itemOrder>0</itemOrder>
  <id>SubTab22_0</id>
  <binding></binding>
  <caption>頁籤0</caption>
  <multiZhMap id="565"/>
  <hidden>false</hidden>
</com.dsc.nana.domain.form.ListItem>
```

注意 `<id>` 的命名慣例是 `{父元件ID}_{序號}`。
**`caption` 是設計師實填的欄位標題，實測 100% 有中文**（`7_proc_export` 的實測結論），
所以表格明細的 IR 必須填 `caption`，不能省。

## 5. rwdLayout —— 版面

內容是逃脫過的 JSON 陣列，一個元素等於一列：

| 形式 | 用途 |
|:---|:---|
| `{"rowType":"Title","id":"Title1"}` | 整列型元件（標題、分隔線） |
| `{"row":[3,3,3,3],"column":[[12],[12],[12],[12]],"elements":[[{"id":"A"}],[{}],[{}],[{"id":"B"}]]}` | 一般格線列 |

- `row` 是各格佔的欄寬（總和 12）。
- `column` 是每格內部再切的欄寬。
- `elements` 與 `row` 一一對應；`{}` 代表空格。
- **元件 ID 在此處也要出現一次**。`1_xml_tool` 改 ID 時必須同步改這裡，
  否則 BPM Web 設計器會拋 `TypeError: Cannot read properties of null (reading 'type')`
  （PRD.md 已記載的實際故障）。

生成時的注意：`rwdLayout` 裡的 ID 集合，必須與 `elementDefinitions` 裡的 ID 集合**完全一致**，
多一個或少一個都會讓設計器開不起來。這是自檢階段必查的一項。

## 6. script / mobileScript

- 內容是**逃脫過的 JavaScript 字串**（`&lt;` `&gt;` `&amp;` `&quot;`）。
- `1_xml_tool` 已有「萃取成 `.js` → 編輯 → 逃脫回寫」的雙向功能，**直接沿用，不要重寫**。
- 表格元件的事件函式與物件變數帶有元件 ID：`${GridId}_add_onclick`、`${GridId}Obj`，
  改 ID 時要一起改（`form_handler` 已處理）。
- 腳本內容的規範另見 [表單腳本手冊.md](表單腳本手冊.md)。

## 7. 生成流程（組裝器該做的事，依序）

```
1. 讀 form_ir.json，校驗 ID 合法性與唯一性
2. 依 fields 順序，為每個欄位挑對應的元件樣板
3. 為每個有 label 的欄位，額外產生一個 lbl_ 開頭的 Label 樣板
4. 填入 IR 決定的那幾格（id / name / textValue / caption / controlType / 選項…）
5. 依 layout 產生 rwdLayout 的逃脫 JSON
6. 產生 script（生命週期骨架 + 事件函式空殼），逃脫後寫入 <script>
7. ★ 全檔重新編號 XStream id（1…N），同步重寫所有 reference
8. 寫檔（UTF-8，比照來源檔決定是否帶 BOM）
9. 自檢：用 form_handler.extract() 反解，與 IR 逐項比對
```

第 7 步一定要在最後、一次做完。邊插邊編號必定出錯。

## 8. 陷阱清單

| 陷阱 | 後果 | 對策 |
|:---|:---|:---|
| 用 lxml / ElementTree 重新序列化 | XStream 參照與空白格式被破壞，匯入失敗 | 一律走 `core/xml_utils.py` 的字串區間法（AGENTS.md 7.2） |
| 插元件後沒重編 id | ⚠️ 推測會匯入失敗或元件遺失 | 第 7 步 |
| `rwdLayout` 與 `elementDefinitions` 的 ID 不一致 | 設計器 `Cannot read properties of null` | 自檢比對兩邊 ID 集合 |
| 忘了產生 Label | 表單上沒有欄位名稱，稽核匯出只剩 ID | 每個 `label` 非空的欄位都要配一個 Label |
| 按鈕 ID 沒有 `Button` / `Btn` 結尾 | 流程權限矩陣把它歸類成欄位 | 命名規範（IR 手冊第 7 節） |
| 元件 ID 用了中文或減號 | ID 會成為 XML 標籤名，權限字串直接壞掉 | `^[A-Za-z_][A-Za-z0-9_]*$` |
| 直接覆寫 `samples/` 原檔 | 失去比對基準 | 一律另存，沿用 `已完成_` 命名精神 |
