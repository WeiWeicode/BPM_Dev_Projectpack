# 從需求生成手冊 —— 給一張圖或一份欄位清單，做出表單與流程

⑧ 目前有三條產出路線，這份手冊講**第三條**：

| 路線 | 手上有什麼 | 入口 |
|:---|:---|:---|
| 從空白範本長出來 | 只要一個空殼 | `tools/new_project.py` |
| 照著線上既有流程做 | 線上有一支可以照抄 | [線上抓取手冊](線上抓取手冊.md) → `tools/build_from_online.py` |
| **從需求生成** | **只有一張截圖／一份欄位清單／一段口述** | **`tools/build_from_spec.py`** |

工具：[`tools/build_from_spec.py`](../tools/build_from_spec.py)

---

## 1. 提示詞（給 AI agent 用）

要 agent 做這件事時，照下面這樣講就夠了：

```
使用 8_BPMAIworker，請做出人員需求申請單，參考圖片欄位跟流程關卡
```

（連同表單截圖、流程截圖一起貼上。沒有圖就直接列欄位名稱，或口述要哪些關卡。）

其他等價講法：

```
使用 8_BPMAIworker，做一張出差申請單，欄位有：申請人、出差起訖日、
目的地、事由、預估費用；關卡走 填表人 → 直屬主管 → 財務 → 結案
```

### agent 收到這種指令時的固定五步

| 步 | 動作 | 產出 |
|:---|:---|:---|
| 1 | 讀圖／讀清單，把**欄位中文名、型別、版面分列、選項**與**關卡順序**列出來，不確定的先問 | 盤點清單 |
| 2 | 依第 3 節的命名規則，把每個欄位與關卡**翻成英文 ID**；中文名一字不改照抄 | ID 對照表 |
| 3 | 寫 `form_ir.json` 與 `process_ir.json`（格式見 [AI產生規格_IR.md](AI產生規格_IR.md)） | 兩份 IR |
| 4 | 跑 `build_from_spec.py` 組裝 | `.form` / `.js` / `.bpmn` |
| 5 | 讀工具印出的 **[失敗] 與 ⚠️**，回報還要人工做什麼 | 交付說明 |

**AI 只做第 1～3 步。**第 4 步之後全是確定性程式：XStream 連號 `id`、32 碼 OID、
二次逃脫的權限字串、67 個關卡樣板標籤，一律由程式配
（[README.md](../README.md) 第 2 節：這三件事 LLM 逐字生成必然出錯，而且錯了不報錯）。

### 一定要先問、不要猜的三件事

1. **有沒有既有的線上表單可以照抄**。有的話走[線上抓取手冊](線上抓取手冊.md)那條路，
   欄位 ID 與腳本能直接沿用，比重畫準。
2. **表單代號與流程代號**。沒指定就依表單中文名取一個英文名，並在回報時講清楚取了什麼。
3. **關卡的實際簽核者**。圖上寫「人事」「核決層級」，但本工具產不出這些執行者型別
   —— 見第 6 節，這是要人在設計師裡指定的。

## 2. 指令

```bash
python 8_BPMAIworker/tools/build_from_spec.py --form-ir <form_ir.json> --process-ir <process_ir.json> --out <輸出目錄>
```

| 參數 | 說明 |
|:---|:---|
| `--form-ir` | 必填。表單的 IR |
| `--process-ir` | 選填。不給就只產表單（流程要另外跑 `new_project.py`） |
| `--script` | 選填。指定表單 JavaScript 檔；不給就依 IR 的 `script` 段產生函式空殼 |
| `--out` | 必填。輸出目錄，會長出 `表單/` 與 `流程/` 兩個資料夾 |

產出：

```text
<輸出目錄>/
├── form_ir.json、process_ir.json     ← AI 寫的，留著當下次改版的依據
├── 表單/<formId>.form
├── 表單/<formId>.js
└── 流程/<processId>.bpmn
```

**IR 有任何一項不合法就整份不組裝。** 欄位 ID 打錯不會讓匯入失敗，
是執行期讀取時才炸（⑤ `5_ws_explorer` 手冊記載的同型地雷），所以一律先擋。

## 3. 命名規則 —— 中文名照抄，ID 翻成英文

這是這條路線最容易做壞的一段，規則全文在
[AI產生規格_IR.md 第 7 節](AI產生規格_IR.md#7-命名規範給-ai-的硬規則)，這裡只講怎麼套：

| 對象 | 規則 | 例（人員需求申請單） |
|:---|:---|:---|
| 欄位中文名 | **一字不改照抄圖上的字**，含括號與全形標點 | `性別(僅供內部參考，對外刊登一律依性平法規定)` |
| 欄位 ID | 英文語意名 + **型別後綴**，首字大寫駝峰 | 填表人 → `FillerTextBox`、需用日期 → `NeedDate` |
| 關卡中文名 | 照抄圖上的字 | `人力資源部門主管` |
| 關卡 ID | 英文語意名 + 關卡型別後綴 | 核決層級 → `ApprovalLevelUserTask`、通知人事 → `NotifyHRSendTask` |

型別後綴不是裝飾，**看 ID 就知道是什麼元件**，對權限時省掉來回查表；
按鈕更是功能性的——`bpmn_handler` 依 ID 結尾是不是 `Button` / `Btn`
把權限項分成按鈕區與欄位區，少了後綴權限矩陣就對不上。

### 翻譯的取捨

- **意譯優先，不要逐字直譯**：`進用理由` → `HireReason`，不是 `AdmissionReason`。
- **公司慣用的英文縮寫維持原樣**：人事／人力資源 → `HR`，工程變更 → `ECR`。
- **同一支表單內用同一套詞**：`Dept` 與 `Department` 不要混用。
- **保留 ID 不可自行命名**：附件一律 `Attachment`、單號一律 `SerialNumber`，
  改了不會報錯，是匯入後功能失效才發現（IR 手冊 7.4）。工具會擋。

### 人員需求申請單的實際對照（節錄）

| 圖上的中文 | 欄位 ID | 型別 |
|:---|:---|:---|
| 填表人 | `FillerTextBox` | TEXTBOX |
| 申請人 | `ApplicantDialogInputLabel` | DIALOGINPUTLABEL（帶 `...` 開窗那種） |
| 需用日期 | `NeedDate` | DATE |
| 來源管道 | `SourceChannelCheckBox` | CHECKBOX |
| 進用理由 | `HireReasonRadio` | RADIO |
| 需求職等 | `JobGradeDropDown` | DROPDOWN |
| 工作內容說明 | `JobContentTextArea` | TEXTAREA |
| 特殊作業體格檢查 | `SpecialHealthCheckRadio` | RADIO |
| 填表人（關卡） | `ApplyUserTask` | UserTask |
| 通知 人力資源部門主管 | `NotifyHRManagerSendTask` | SendTask |

## 4. 看圖要判斷的四件事

| 看到什麼 | 判成什麼 | 注意 |
|:---|:---|:---|
| 空白長框 | `TEXTBOX`；框很高就是 `TEXTAREA` | — |
| 框旁邊有 `...` 按鈕 | `DIALOGINPUTLABEL`（開窗選人／選單號） | 不是 TEXTBOX + BUTTON 兩個元件 |
| `○` 圓鈕 | `RADIO`，同一組只能選一個 | 選項順序決定執行期 `<欄位ID>_0`、`_1`… 的 DOM id |
| `□` 方塊 | `CHECKBOX`，可複選 | 同上 |
| 有 `▼` 的框 | `DROPDOWN` | — |
| 寫著 `Date` 的框 | `DATE` | — |
| 「表單下載」這種底線文字 | `LINK` | — |
| 「附檔」按鈕 | `ATTACHMENT`，ID 一律 `Attachment` | 不要做成 BUTTON |

**選項的 `value` 與 `caption` 要分開想**：畫面顯示「外部召募」，
存進資料庫的值建議用 `EXTERNAL` 這種英文碼，之後接 ERP 或寫報表才不會拿到一堆中文。
兩個都要寫，只寫顯示文字會讓存進去的值變成中文。

## 5. 支援的元件型別

`type` 一律大寫，對應到教材檔 `原檔案-quickDevTestForm.form` 的實際片段。
`controlType` 是實測值，不是照名稱猜的：

| IR `type` | controlType | 後綴 |
|:---|:---|:---|
| `TEXTBOX` | `INPUT_TYPE` | `TextBox` |
| `TEXTAREA` | `INPUT_TEXTAREA_TYPE` | `TextArea` |
| `PASSWORD` | `INPUT_SECRET_TYPE` | — |
| `HIDDEN` | `HIDDEN_TYPE` | `Hidden` |
| `RADIO` | `SELECT_RADIO_TYPE` | `Radio` |
| `CHECKBOX` | `SELECT_CHECK_TYPE` | `CheckBox` |
| `DROPDOWN` / `SELECT` | `SELECT_COMBO_TYPE` | `DropDown` |
| `LISTBOX` | `SELECT_LIST_TYPE` | `ListBox` |
| `DATE` / `DATETIME` / `TIME` | `DIALOG_DATE` / `DIALOG_DATETIME` / `DIALOG_TIME` | `Date` / `Time` |
| `BUTTON` | — | **`Button` 或 `Btn`（強制）** |
| `ATTACHMENT` | — | 固定 `Attachment` |
| `SERIAL_NUMBER` | — | 固定 `SerialNumber` |
| `TITLE` / `LABEL` / `HORIZONTAL_LINE` | — | `Title` / — / — |
| `LINK` / `IMAGE` / `BARCODE` / `QRCODE` / `HANDWRITING` | — | 同名 |
| `DIALOGINPUT` / `DIALOGINPUTLABEL` / `DIALOGINPUTMULTI` | `DIALOG_INPUT` 系列 | 同名 |
| `DOUBLETEXT` | — | `DoubleTextBox` |

### 目前做不到的兩種

| 型別 | 為什麼 | 怎麼辦 |
|:---|:---|:---|
| `LIST`（表格明細） | `listItems` 內每一欄都要另外繫結一個輸入元件，這段還沒做 | 走 `build_form.py`，或匯入後在設計師補 |
| `SUBTAB`（分頁） | `rwdLayout` 的 `tabs` 結構還沒做 | 匯入後在設計師補 |

工具遇到這兩種會**直接擋下來說明原因**，不會產出一個看起來對、匯進去才壞的檔案。

## 6. 版面：12 欄格線

IR 的 `layout` 只寫人看得懂的三個數字，其餘由組裝器換算：

```jsonc
"layout": { "row": 4, "col": 2, "span": 6 }   // 第 4 列、該列第 2 格、佔 6 欄
```

| 規則 | 說明 |
|:---|:---|
| 同一 `row` 的 `span` 加總不得超過 12 | 超過就整份不組裝並指出是哪一列 |
| 加總不到 12 | 自動補一格空的填滿（與教材檔的寫法一致） |
| `TITLE`、`HORIZONTAL_LINE` | 整列型，不需要 `col` / `span`，也不能與其他欄位同列 |
| `HIDDEN` | **一律不進版面**。放進格線畫面不會畫它，腳本 `document.getElementById` 就抓不到 |
| 沒寫 `layout` | 排在最後，每列一個、`span: 12` |

看圖分列時：**視覺上同一橫排的欄位就給同一個 `row`**。
兩欄並排用 `span: 6`、三欄用 `4`、四欄用 `3`、整列用 `12`。

> ⚠️ 線上實際檔案只看得到 `3` 與 `12` 兩種寬度。`4` 與 `6` 依格線定義應該可行，
> 但**還沒實際匯入驗證過**（PLAN.md 第 7 節第 3 點的未知數）。

## 7. 流程關卡與執行者（這一節請整段讀完）

支援四種關卡：

| `type` | 用途 | 片段來源 |
|:---|:---|:---|
| `StartEvent` | 起點，一支流程剛好一個 | 空白範本 |
| `UserTask` | 要人簽核的關卡 | 空白範本 |
| `SendTask` | 系統自動通知，**不會停下來等人** | 教材檔 |
| `EndEvent` | 終點 | 空白範本 |

組裝前會走一次圖，**起點到不了的關卡、沒有出線的關卡都會被擋下來**
—— 那種流程匯得進去也跑不動。

### ⚠️ 執行者只有兩種，其餘要人工指定

| IR `participant` | 意思 |
|:---|:---|
| `PROCESS_REQUESTER` | 流程申請人本人 |
| `MANAGER` | 申請人的直屬主管 |

空白範本只帶這兩種，兩種都隨範本匯入過。線上實際還有
`MANAGER_OF_ORGANIZATION_UNIT`（指定部門的主管）、`FORM_FIELD_DATA`（由表單欄位指定人）等，
但**它們的 XML 寫法本工具沒有實測過，一律擋下來**（AGENTS.md 第 6 節：做不到就說做不到）。

所以像「人事確認」「人力資源部門主管」「核決層級」這種關卡：

1. IR 先寫 `MANAGER` 讓流程長得出來；
2. **回報時一定要明講**「這幾關的執行者是佔位用的，匯入設計師後要改成實際的部門或角色」。

`SendTask` 的通知對象同理，而且**通知內容（主旨與內文範本）本工具不產**，也要在設計師裡設。

### 欄位權限

只寫「這一關要放開的欄位」：

| 想要的效果 | 怎麼寫 |
|:---|:---|
| 可編輯 | `"欄位ID": "ENABLED"` |
| **唯讀** | **不要列出這個欄位** |
| 隱藏 | `"欄位ID": "INVISIBLE"` |
| 完全控制 | `"欄位ID": "FULL_CONTROL"`（極罕見） |

不要發明 `READ_ONLY` / `HIDDEN` / `DISABLED`，資料庫實測只有上面三種值（AGENTS.md 7.3）。
`SendTask` 沒有人會開表單，設了權限沒有意義，工具會擋。

## 8. 表單 JavaScript

不給 `--script` 時，工具依 IR 的 `script` 段產生：

- 五個生命週期函式的空殼（`formCreate` / `formOpen` / `formSave` / `formClose` / `formDispatch`）
- `events` 列到的事件函式空殼，函式名就是 `<欄位ID>_<事件>`，內容是一行 `// TODO`

**業務邏輯不自動生成。** 要寫連動邏輯（例如「選了『臨時人力需求』才開放工期起訖日」），
先讀 [表單腳本手冊](表單腳本手冊.md)，尤其是頁面已預載哪些 JS、可直呼哪些 DWR 服務
—— 那份手冊的重點是**不要重造已經有的輪子**，也不要用 `document.write` 這類舊寫法。

## 9. 產出後的驗證

工具自己會做這幾項（PLAN.md 的 **L1**）：

| 檢查 | 為什麼 |
|:---|:---|
| 反解 `.form`，欄位數與 IR 逐項比對 | 產出物必須能被 ① `1_xml_tool` 讀回來 |
| 版面裡的每個 ID 都有對應元件 | 設計師照 `rwdLayout` 逐格找元件，找不到就 `Cannot read properties of null` |
| 每個選項都有 `displayValue` 與 `itemValue` | 手拼漏一格，設計師直接開不起來 |
| **配對檢查**：`<pairId>` 不可以是空字串（Label 與分隔線除外） | 空字串會讓設計器把元件當成「只有標籤」，開檔丟 `Cannot read properties of undefined (reading 'id')` |
| **設計器載入模擬**：照 `rwd-node-factory.js` 的 `rebuild()` 走一遍 | L1 只保證「我們讀得回來」，這一項才逼近「設計器開得起來」 |
| 反解 `.bpmn`，關卡／型別／連線／權限與 IR 逐項比對 | 權限漏一項不會報錯，是簽核時才發現改不了 |
| 流程圖節點與關卡一一對應 | 少畫一個節點，設計師畫布就缺一塊 |
| 範本識別字沒有殘留 | 少改一處就靜默綁錯表單 |

**L1 過不代表匯得進去。** L2（匯入設計師能開能存）與 L3（實際跑完一張單）
目前沒有任何自動化手段，只能人工，而且請在 **191 測試區**做（AGENTS.md 8.1）。

## 10. 實例：人員需求申請單

輸入是一張表單截圖與一張流程截圖，agent 寫出兩份 IR 後：

```bash
python 8_BPMAIworker/tools/build_from_spec.py --form-ir 8_BPMAIworker/out/人員需求申請單/form_ir.json --process-ir 8_BPMAIworker/out/人員需求申請單/process_ir.json --out 8_BPMAIworker/out/人員需求申請單
```

得到：36 個欄位、20 列版面、49 個選項的 `.form`，
9 個關卡（含兩個通知）、8 條連線、5 關設了欄位權限的 `.bpmn`，L1 全過。

IR 兩份留在 `out/人員需求申請單/`，要改欄位就改 IR 再跑一次
—— 同樣的 IR 一定產出同樣的檔案，不要去手改產出的 XML。

## 11. 已知限制

- **`LIST` 與 `SUBTAB` 產不出來**（第 5 節）。
- **執行者只有兩種**（第 7 節），其餘要在設計師裡指定。
- **通知關卡的主旨與內文範本不產**。
- **沒有分支**：`ParallelGateway`、`DecisionRuleTask` 都還沒做，目前只能組一條直線流程。
- **版面像素級還原不了**：格線只能切 12 欄，要細調得進設計師拉。
- **腳本只有殼**，業務邏輯要人寫。
- **L2 / L3 仍是人工**：`check_designer_load` 只模擬了設計器的**載入分類與版面走訪**，
  沒有模擬 `transformProperties`、`setupLabel` 等後續步驟，
  也完全沒有涵蓋存檔與發佈。**模擬過不等於設計器開得起來**，
  第一次匯入請在 191 測試區做，並把結果回報進 [PLAN.md](../PLAN.md) 第 1 節。

### 2026-09-10 的第一次匯入：踩到空 `<pairId>`

人員需求申請單匯進設計器時跳 `TypeError: Cannot read properties of undefined (reading 'id')`
（流程檔正常，只有表單開不起來）。原因是隱藏欄位與超連結被產成「沒有配對標籤、
`<pairId>` 是空字串」，設計器會把這種元件當成「只有標籤沒有輸入元件」。
細節與規則寫在 [表單生成手冊第 3 節](表單生成手冊.md#3-元件與中文標籤的配對機制)，
組裝器已修正並補上兩道檢查。**修正後的檔案尚未再次匯入驗證。**
